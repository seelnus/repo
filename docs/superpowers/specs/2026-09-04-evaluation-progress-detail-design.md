# 360 环评员工评价进度明细设计

## 目标

在 360 环评批次的“统计报告 / 评价数据”列表中，为每名员工增加“进度查看”入口。管理员点击后，可以从该员工作为评价人的视角查看：应评价哪些人、已经评价哪些人、尚未评价哪些人，以及自评是否完成。

本功能只补充进度查看能力，不改变评价关系生成、答卷提交、结果计算和个人报告逻辑。

## 页面入口

- 入口位置：“统计报告 / 评价数据”表格的“操作”列。
- 操作顺序：“进度查看”在“查看报告”之前。
- “查看报告”仍然展示该员工作为被评人的结果；“进度查看”展示该员工作为评价人的任务，两个入口含义明确区分。

## 交互设计

点击“进度查看”后，使用 Ant Design Modal 打开进度弹窗。

弹窗标题：`员工姓名 · 评价进度`。

### 汇总区

顶部横向展示四项数据：

- 应评价：该员工当前批次全部评价任务数，包含自评。
- 已完成：已经绑定有效答卷的任务数。
- 未完成：应评价减已完成。
- 完成率：已完成 / 应评价；没有任务时显示 `—`。

### 分类明细区

按评价关系类型展示以下行：

1. 自评。
2. 同事互评。
3. 领导评价，仅当当前员工存在此类任务时展示。

每行包含：

- 任务类型。
- 完成率。
- 已评价人员。
- 未评价人员。

人员使用紧凑标签展示。名单较多时，明细区在弹窗内部滚动，不扩大整个页面高度。鼠标悬停人员标签时，可查看该评价关系命中的互评小组；同一评价人与被评人因多个小组重合只显示一个任务，互评小组作为来源信息展示。

没有评价任务时展示 Ant Design Empty，并提示“该员工当前没有评价任务”。某个分类没有人员时显示 `—`，不渲染空标签容器。

## 数据口径

进度以当前批次 `EvalRelation` 为唯一任务来源，查询条件为：

- `cycleId` 等于当前批次。
- `raterContactId` 等于当前员工。

任务完成必须同时满足：

- `responseId` 不为空。
- 关系状态为 `submitted`。

答卷作废时现有逻辑会清除关系上的 `responseId` 并将状态恢复为 `pending`，因此作废任务自动重新归入“未完成”。恢复答卷后重新归入“已完成”。

名称优先使用本批次参与人快照 `nameSnapshot`，不存在快照时再使用当前联系人名称，避免联系人后续改名影响本批次展示。

## 后端设计

新增接口：

`GET /api/admin/eval/cycles/:id/progress/:contactId`

接口职责：

1. 校验批次存在。
2. 校验员工属于当前批次。
3. 查询该员工作为评价人的全部关系。
4. 批量加载被评人快照或联系人名称。
5. 对自动互评关系计算共享互评小组，人工关系标记为人工配置。
6. 返回汇总信息及按关系类型分组的已完成、未完成名单。

建议响应结构：

```json
{
  "participant": {
    "contactId": 132,
    "name": "丁史远"
  },
  "summary": {
    "total": 2,
    "completed": 0,
    "pending": 2,
    "completionRate": 0
  },
  "groups": [
    {
      "type": "self",
      "label": "自评",
      "total": 1,
      "completed": [],
      "pending": [
        {
          "contactId": 132,
          "name": "丁史远",
          "sharedGroups": []
        }
      ]
    },
    {
      "type": "peer",
      "label": "同事互评",
      "total": 1,
      "completed": [],
      "pending": [
        {
          "contactId": 187,
          "name": "查曌",
          "sharedGroups": [
            {
              "name": "查曌激活组",
              "path": "公司组织/员工私人号/运营部/沈立大区部/沉默粉激活组/查曌激活组"
            }
          ]
        }
      ]
    }
  ]
}
```

接口不返回答卷内容或评分数据，避免进度弹窗暴露不必要信息。

## 前端设计

在 `EvalResultsPanel` 中增加：

- 进度弹窗状态。
- 单员工进度加载状态。
- `openProgress(contactId)` 请求方法。
- “进度查看”按钮。
- 独立的 `EvalRaterProgressModal` 展示组件。

视觉延续现有 Ant Design 风格：白色弹窗、清晰分区、蓝色完成标签、橙色待完成标签。信息重点是人员和任务状态，不增加装饰性图形。

## 错误处理

- 员工不在当前批次：返回 404，并提示“该员工不在本批次参评范围”。
- 批次不存在：沿用现有批次不存在错误。
- 网络或接口失败：弹窗不打开，页面提示“评价进度加载失败”。
- 快照外联系人缺失：名单名称回退为 `#联系人ID`，保证任务不会从统计中消失。

## 测试与验收

后端测试覆盖：

1. 自评和互评同时统计。
2. 已提交任务进入已完成名单。
3. 待提交及已作废任务进入未完成名单。
4. 多部门重复命中只保留一条评价关系，并返回全部共享小组。
5. 人工关系正常展示。
6. 非批次员工返回 404。

前端验收覆盖：

1. “进度查看”和“查看报告”语义及入口均正确。
2. 汇总数字与分类名单数量一致。
3. 自评单独显示。
4. 长名单在弹窗内部滚动。
5. 空任务、加载失败和名称回退均有明确表现。
6. 本地批次中“丁史远”能够看到自评和对“查曌”的互评任务。

## 非本次范围

- 不增加催办、短信或消息通知。
- 不提供批量导出个人进度名单。
- 不修改个人报告的评分与匿名反馈展示。
- 不改变现有关系生成及多部门去重规则。
