# 360 环评关系明细自动刷新设计

**日期**：2026-08-28

**状态**：方案 A 已确认，待代码实施

## 1. 背景与根因

360 环评“关系复核”页面下方已经存在关系明细表，后端 `GET /api/admin/eval/cycles/:id/relations` 也会返回评价人、被评人、关系类型、来源和填写状态。

当前空表不是关系未生成：数据库和接口均能返回自动关系。实际根因是 `RelationsTab` 只在组件初次挂载或批次 ID 变化时加载。管理员进入页面后再点击“一键生成普通员工评价关系”，生成区和复核区没有通知关系明细重新请求，明细表继续保留生成前的空数组，直到整页刷新或重新进入页面。

## 2. 目标与范围

### 2.1 目标

- 关系生成成功后，关系明细立即自动展示最新数据。
- 人工添加或删除关系后，复核列表与关系明细保持同步。
- 管理员仍可单独手动刷新关系明细。
- 接口失败时明确提示，不把加载失败伪装成“暂无数据”。

### 2.2 展示范围

关系明细展示当前批次的全部关系：

- 来源：自动生成 `auto`、人工添加 `manual`。
- 类型：自评 `self`、他评 `peer`、领导评价 `leader`。
- 状态：待填、已填。

不新增数据库字段，不修改关系生成、唯一性、提交或删除规则。

## 3. 组件协调设计

### 3.1 共享刷新信号

在 `EvalPeopleTab` 中增加数值型 `relationRevision`。每次关系数据发生变化时递增：

```text
生成成功 ─┐
人工添加 ─┼─> relationRevision + 1
删除关系 ─┘
              ├─> ReviewTab 重新加载
              └─> RelationsTab 重新加载
```

该信号只负责通知，不保存关系数据。`ReviewTab` 与 `RelationsTab` 仍分别调用现有接口，保持组件边界和现有后端数据口径。

### 3.2 组件接口

- `GenerateTab` 新增 `onRelationsChanged` 回调，生成接口成功后调用。
- `ReviewTab` 新增 `refreshKey`，加载 Effect 依赖 `cycleId` 和 `refreshKey`。
- `RelationsTab` 新增 `refreshKey` 与 `onRelationsChanged`。
- 人工添加或删除成功后，`RelationsTab` 调用 `onRelationsChanged`，由父组件统一触发两个区域刷新。

不使用定时轮询，不从生成报告拼装关系明细，也不让兄弟组件直接调用彼此的内部方法。

## 4. 关系明细表

### 4.1 字段

明细表继续展示：

| 列 | 展示规则 |
| --- | --- |
| 评价人 | `raterName` |
| 被评人 | `rateeName` |
| 类型 | 自评、他评、领导评价标签 |
| 来源 | 自动、人工标签 |
| 已填 | 已填、待填标签 |
| 操作 | 未填写关系允许删除，已填写关系禁用删除 |

类型和来源使用不同颜色的 Ant Design Tag，提升扫读效率。分页保持每页 20 条，并显示“共 N 条”。

### 4.2 工具栏

红框区域顶部保留“人工添加关系”，并增加：

- 当前关系总数，例如“共 20 条关系”。
- “刷新明细”按钮，只重新加载关系明细，不触发重新生成。

### 4.3 空状态

- 加载成功且确实为 0 条：显示“暂无评价关系，请先生成或人工添加”。
- 加载失败：保留原有数据，并提示“关系明细加载失败，请重试”。
- 加载中：使用 Table 的 loading 状态，不提前显示空状态。

## 5. 数据流

### 5.1 自动生成

1. 管理员点击“一键生成”。
2. 后端生成关系并返回报告。
3. `GenerateTab` 展示生成报告。
4. 调用 `onRelationsChanged`。
5. `ReviewTab` 和 `RelationsTab` 分别重新请求复核数据和关系明细。
6. 明细表展示本次生成的全部评价人—被评人关系。

### 5.2 人工添加与删除

1. 人工添加或删除接口成功。
2. 关闭弹窗或显示成功提示。
3. 调用 `onRelationsChanged`。
4. 复核统计和明细表同步刷新。

接口失败时不递增刷新信号，保留当前列表，并展示后端错误信息。

## 6. 并发与异常

- 生成、添加或删除按钮继续使用现有 loading 状态，防止重复提交。
- 多次快速触发刷新时，以最后完成的请求结果为当前数据；本次不引入缓存层。
- 关系明细加载增加 `catch`，避免未处理 Promise 和静默空表。
- 切换批次后仍以新 `cycleId` 重新加载，不复用旧批次数据。

## 7. 测试与验收

### 7.1 自动刷新

- 初始没有关系时明细表显示明确空状态。
- 点击生成成功后，无需整页刷新即可看到全部自动关系。
- 上方复核统计与下方关系明细数量一致。

### 7.2 展示口径

- 自评行的评价人和被评人为同一人，类型显示“自评”。
- 普通互评显示不同评价人和被评人，类型显示“他评”。
- 人工领导关系显示“领导评价”和“人工”。
- 自动关系显示“自动”。
- 已提交关系显示“已填”，删除按钮禁用。

### 7.3 人工操作

- 人工添加成功后，复核区和明细区同时刷新。
- 删除未填写关系后，该行消失，复核统计同步变化。
- 添加或删除失败时保持当前数据并展示错误。

### 7.4 回归

- 生成报告数字和警告保持不变。
- 重新生成仍只覆盖自动关系，不删除人工关系。
- 关系唯一性和已填关系不可删除规则保持不变。
- 不影响员工填写任务、评分和报告。

## 8. 验收标准

1. 生成关系后，红框区域自动展示关系明细，无需刷新整页。
2. 每行明确显示评价人、被评人、类型、来源和填写状态。
3. 自动、人工、自评、他评和领导评价均能正确展示。
4. 生成、人工添加和删除后，上下两个区域保持同步。
5. 真正无关系和接口加载失败具有不同提示。
