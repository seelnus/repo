# 组织架构父子连接线调整设计

## 状态

已确认方案 A，等待用户审阅本文档后实施。

## 背景

当前组织架构采用按层级横向展开的列布局。第二级部门出现时，连接线从父部门所在整列的中点发出，而不是从实际被展开的父节点发出。当父节点位于列表上方或下方时，父子关系看起来悬空，无法直观判断下级部门属于哪个父部门。

## 目标

- 保留现有“点击部门，下一层向右展开”的交互。
- 连接线明确表达“父节点 → 子部门集合”的关系。
- 视觉关系参照钉钉：父节点右侧出线，接入子级统一竖向主干，再分支连接每个子节点。
- 不修改组织数据、后端接口、部门层级规则和员工归属逻辑。

## 页面结构

每一级部门列拆分为两部分：

1. 列标题：显示父部门名称和“下级部门”。
2. 分支容器：承载该父部门的所有直接子部门。

分支容器负责绘制子级竖向主干；每个子部门节点从主干获得一条水平支线。只有真正被展开且右侧存在下一列的父节点绘制向右出线，避免连接线从整列中心错误发出。

```text
父部门 ─────┬── 子部门 A
             ├── 子部门 B
             └── 子部门 C
```

公司节点到一级部门使用同一套“出线—主干—分支”表达。

## 视觉规则

- 默认连接线使用低对比度蓝灰色，保持页面安静。
- 当前展开父节点的出线使用品牌浅蓝色，帮助用户追踪当前分支。
- 连接线与节点垂直中心精确对齐。
- 竖向主干只覆盖第一个和最后一个子节点的中心，不延伸到列标题或新增按钮。
- 单个子部门时退化为一条水平连接线，不出现多余竖线。
- 缩放、横向滚动、窄屏纵向布局继续可用。

## 实现边界

- 调整 `OrganizationContactsPage.tsx` 中部门列的局部 DOM 结构和展开状态类名。
- 调整 `index.css` 中组织图连接线伪元素与响应式规则。
- 不引入 SVG、Canvas 或第三方组织图依赖。
- 不改变 Ant Design 组件体系。

## 验收标准

- 点击“运营部”后，出线从“运营部”卡片右侧中心开始。
- 湖州部、运营大本营、开发组等直接子部门共享一条竖向主干，并各自通过水平支线连接。
- 点击任意其他一级或多级部门时，连接关系随当前展开分支正确切换。
- 新增一级部门按钮、列标题不被连接线穿过。
- 70%–130% 缩放下连接线仍与节点对齐。
- 前端构建通过，并在本地浏览器完成一级、多级与单子节点场景检查。
