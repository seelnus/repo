# 360 环评评分单选题前后台界面改造设计

**日期**：2026-08-28

**状态**：员工填写端和后台编辑端视觉方案均已确认，待代码实施

**选定方案**：C「行为卡片 + 渐进案例」

## 1. 背景与目标

当前员工填写端的 `evaluation_score` 评分题使用自定义按钮列表，后台模板编辑端则把题目字段和 0–5 分配置连续平铺在一个 Card 中。两端虽然可以完成操作，但题目、分值、行为描述和案例设置的视觉层级较弱，整体观感偏朴素，与项目现有 Ant Design 界面不够一致。

本次参考腾讯问卷的单列评分结构，采用 Ant Design 的 Radio、Card、Form、Checkbox、描边、主色和输入状态，统一后台配置与员工填写的视觉语言，提升编辑、扫读、选中反馈和案例填写体验。

## 2. 改造范围

本次修改两处 `evaluation_score` 界面：

- 员工填写端：评分选项视觉与点击交互、题号与维度层级、案例输入渐进联动、响应式布局和错误提示。
- 后台模板编辑端：题目编辑卡层级、基础字段分区、0–5 分行为选项配置行、案例必填分值的就近设置和只读状态。

以下内容保持不变：

- `evaluation_score` 题型和模板 JSON。
- 答案结构 `{ score, caseText }`。
- 0–5 分取值范围。
- `caseRequiredScores` 决定案例是否必填的规则。
- 后端校验、逐题平均和员工最终评分公式。
- 填空题和普通问卷题型。
- 模板选择、维度管理、添加题目、删除题目和保存模板的现有业务行为。
- 题目拖拽排序、复制题目和整卷预览不在本次范围内；原型中的相关元素仅用于表现视觉层级。

## 3. 视觉结构

### 3.1 题目头部

每道题依次展示：

1. `第 N 题 / 共 M 题`。
2. 维度标签，例如“诚信”。
3. 必填标识和题目标题。
4. 题目补充说明。

维度使用浅蓝色 Ant Design 标签；必填星号使用错误色；标题使用主文本色和中等字重；说明使用次级文本色。

### 3.2 评分选项

0–5 分按单列纵向排列，每个选项整行可点击。选项内部固定为三层信息：

- Radio 圆点。
- 分值，例如“3 分”。
- 行为等级和行为描述。

默认状态为白底、浅灰描边。悬停时使用浅蓝背景和蓝色描边。选中后使用 Ant Design 主蓝色 Radio、蓝色描边、浅蓝底色和轻量外发光。

不使用大面积渐变、彩色分值等级或表情符号，保持人事评价场景的克制和专业感。

### 3.3 案例输入

案例输入采用渐进展示：

- 未选择分值时不显示。
- 选择不要求案例的分值时不显示。
- 选择 `caseRequiredScores` 中的分值时，在选项列表下方展开 Ant Design `Input.TextArea`。
- 展开区域显示“当前分值必填”状态标签、案例提示语和字符计数。
- 从需要案例的分值切换到普通分值时，隐藏输入区，但保留当前 `caseText`，与现有答案行为一致。
- 再切回需要案例的分值时恢复之前输入的内容。

本次不把 TextArea 嵌入每个选项内部，避免六个选项高度不一致和移动端页面跳动。

## 4. 后台模板编辑页

### 4.1 页面结构

保留现有“左侧维度 + 右侧模板内容”的两列结构，不重构模板选择、维度管理和保存流程。评分题 Card 内部改为四层：

1. 题目头部：题号、评分题标签、必答、计入总分和删除操作。
2. 题目内容：标题、补充说明和所属维度。
3. 评分行为选项：0–5 分配置行。
4. 案例填写设置：统一的案例输入提示。

题目头部的必答和计入总分继续映射 `required` 与 `countInScore`。删除操作保持现有行为，不新增拖拽、复制或预览接口。

### 4.2 评分行为选项

0–5 分每个选项使用独立配置行，结构固定为：

- 蓝色浅底分值标识。
- 行为描述 Input。
- “必须填案例”Checkbox。

Checkbox 直接就近修改现有 `caseRequiredScores`：选中时加入该分值，取消时移除该分值。后台不新增每个分值独立的案例提示字段，所有分值继续共用 `casePrompt`。

当前单独放在选项列表下方的 `Checkbox.Group` 将被移除，避免管理员在行为描述和分值勾选区之间反复对照。

### 4.3 编辑状态

- 默认状态使用白底和浅灰描边。
- 鼠标进入配置行时显示 Ant Design 浅蓝背景与蓝色描边。
- 勾选“必须填案例”的配置行使用轻量暖色提示，帮助管理员识别特殊分值。
- 只读批次下所有 Input 和 Checkbox 保持 disabled，仍可完整查看内容。
- 长行为描述允许 Input 正常横向编辑；移动端或窄屏时案例 Checkbox 换到描述下方。

## 5. 员工填写端交互状态

### 5.1 未作答

- 所有 Radio 未选中。
- 案例输入区隐藏。
- 提交时如果题目必填，定位到该题并显示“请选择一个评分”。

### 5.2 已选择普通分值

- 选中行展示蓝色状态。
- 案例输入区隐藏。
- 答案保存为 `{ score, caseText }`，已有案例文字不主动清空。

### 5.3 已选择案例必填分值

- 选中行展示蓝色状态。
- 选项列表下方展开案例输入。
- 案例为空时使用 Ant Design `warning` 状态，并显示“当前分值需要填写具体案例”。
- 输入非空白内容后警告消失。

### 5.4 切换分值

- 点击选项任意区域即可切换 Radio。
- 切换只更新 `score`，保留 `caseText`。
- 不增加二次确认弹窗。

## 6. 布局与响应式

- 桌面端继续使用当前填写页面内容宽度，不重构整页导航。
- 评分选项保持单列，确保长行为描述具有完整阅读空间。
- 选项最小点击高度不低于 52px。
- 移动端缩小左右内边距，分值列从约 62px 缩至约 50px。
- 移动端案例输入区不保留左侧缩进，使用整行宽度。
- 长文本允许自然换行，不截断、不使用横向滚动。
- 后台编辑端在 900px 以下让维度卡和题目编辑区改为单列，评分配置行允许案例 Checkbox 换行。

## 7. 组件边界

现有 `EvalQuestionField` 继续负责单道评分题，内部拆分清晰的展示单元：

- 题目外围信息仍由填写页题目循环负责。
- `EvalQuestionField` 负责 Radio.Group、评分选项卡和案例 TextArea。
- 评分选项使用 Ant Design `Radio.Group` 与 `Radio` 保留键盘选择和语义。
- 后台评分题配置提取为局部 `EvalScoreQuestionEditor`，通过 `question`、`readonly` 和 `onChange` 接收数据，不直接负责模板保存。
- 后台配置行继续生成现有 `options` 和 `caseRequiredScores`，不引入新的前端数据结构。
- CSS 类分别使用 `eval-score-fill-*` 与 `eval-score-editor-*` 前缀，避免填写端和模板编辑端互相污染。

不在本次改造中拆分整个 `EvalPages.tsx`，避免引入无关重构。

## 8. 可访问性

- 使用真实 Radio 控件，不仅依赖按钮样式。
- 支持 Tab 聚焦和方向键切换。
- 选中状态不能只靠背景色，同时有 Radio、描边和文字状态变化。
- 焦点态使用清晰的 Ant Design 蓝色外框。
- 错误提示与对应题目、案例输入在视觉上相邻。
- 后台案例 Checkbox 使用真实 Ant Design Checkbox，并保留可读标签。

## 9. 验证与测试

### 9.1 员工填写端行为

- 0–5 分均能选择并正确更新答案。
- 整行点击与 Radio 点击行为一致。
- 选择 0、4、5 分时按当前默认模板展开案例输入。
- 选择 1、2、3 分时隐藏案例输入。
- 多次切换分值不会丢失已输入的 `caseText`。
- 已保存答案重新进入时正确恢复分值、选中态和案例内容。

### 9.2 后台编辑端行为

- 修改 0–5 分行为描述后，保存和重新进入均正确恢复。
- 在分值行勾选或取消“必须填案例”后，`caseRequiredScores` 正确增删且不产生重复值。
- 必答、计入总分、题目标题、说明、维度和案例提示仍能正常编辑。
- 只读批次不能修改任一配置。
- 删除评分题和添加评分题、填空题的行为保持不变。

### 9.3 校验回归

- 必填评分题未选择时仍阻止提交。
- 案例必填分值缺少非空白案例时仍阻止提交。
- 普通分值允许案例为空。
- 后端答案格式和校验结果不变。

### 9.4 视觉回归

- 桌面端六个选项对齐且长文本不溢出。
- 375px 宽度下无横向滚动。
- Hover、Focus、Selected、Warning 状态可区分。
- 填空题和普通题型样式不受影响。
- 后台评分题编辑卡分区清晰，六个分值行对齐。
- 后台在窄屏下无横向溢出，Checkbox 不遮挡行为描述。

## 10. 验收标准

1. 评分题呈现为专业、克制的 Ant Design 单列行为卡片。
2. 用户可以点击整行选择 0–5 分，并得到明确选中反馈。
3. 案例输入只在模板要求的分值下渐进展开。
4. 分值切换不清空已填写案例。
5. 键盘和移动端可以正常完成选择与案例输入。
6. 评分、校验、答案存储和后端接口行为保持不变。
7. 管理员可以在每个分值行就近配置行为描述和案例必填状态。
8. 后台配置端与员工填写端使用统一的分值、描边、层级和状态语言。
