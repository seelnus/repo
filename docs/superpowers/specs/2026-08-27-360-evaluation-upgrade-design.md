# 360 环评功能正式改造需求规格（方案 B）

**文档版本**：v1.1<br>
**确认日期**：2026-08-27  
**适用项目**：闯货人事管理系统  
**文档状态**：产品规则与模块原型已确认，可进入实施计划阶段

**v1.1 变更**：明确保留原系统全局左侧菜单；360 环评通过批次列表进入内部二级导航；参评人员从联系人模块选择并生成批次快照，不要求每期重复导入人员资料。

---

## 1. 背景与现状

当前系统已经具备 360 环评的基础闭环：

- 环评批次创建、修改和删除。
- 自评、同事他评、领导评价三类评价关系。
- 按单个部门自动生成普通员工自评和组内互评关系。
- 特殊人员通过全局“领导”标签排除后人工配置关系。
- 关系复核、异常提示和人工增删关系。
- 员工企微登录后查看并完成自己的评价任务。
- 管理员导出自评、他评和领导评价原始答卷。

现有实现仍属于“任务分配与填写骨架”，缺少正式环评所必需的评分题模型、模板快照、多小组范围、实时评分、最终结果锁定、汇总报告、个人报告、数据有效性和完整生命周期管理。

### 1.1 当前结构的主要风险

1. 当前评分题固定为 1–10 分，无法表达本次确定的 0–5 分行为等级。
2. 单选题只有选项文本，没有独立数值、维度和案例必填规则，无法稳定计算得分。
3. 自评和他评分别绑定模板，题目 ID 可能不一致，无法可靠合并同一道题的结果。
4. 批次只能按一个部门生成关系，不能在同一批次覆盖多个评价小组。
5. 特殊人员依赖联系人全局“领导”标签，无法表达不同批次中的不同角色。
6. 重新生成自动关系会删除已有自动关系，存在让已提交答卷与批次脱钩的风险。
7. 草稿状态没有在所有填写接口中形成后端强约束。
8. 删除已发布批次可能留下失去批次关系的历史答卷。
9. 环评填写端复用了简化版题目渲染和前端必填校验，未完整复用普通问卷的后端答案校验。
10. 当前只有原始 Excel 导出，没有逐题、维度、员工总分和最终结果快照。

## 2. 建设目标

本次采用“完善现有 360 领域模型”的方案 B，在保留现有问卷、联系人、企微认证、批次和评价关系基础上完成以下目标：

1. 建立一套正式的 0–5 分环评题目模型。
2. 自评和所有他评共用同一份题目模板。
3. 一个批次支持多个部门/小组，各组默认在组内全员互评。
4. 特殊人员在批次内配置，不再依赖联系人全局角色。
5. 支持案例说明，并由管理员配置哪些分值必须填写案例。
6. 建立所有有效答卷等权的评分计算中心。
7. 支持进行中暂定分和锁定后的最终分。
8. 提供评估概览、评价数据、个人报告、原始数据和多类导出。
9. 保护已提交答卷和历史结果，所有敏感操作可审计。
10. 保持现有普通问卷、白名单、联系人和数据统计功能不受影响。

### 2.1 首期不包含

- 自评、同事、领导之间的权重配置。
- 题目权重或维度权重。
- 员工查看自己的汇总报告。
- 向员工公开他评内容或评价人身份。
- 申诉、绩效校准会和审批流。
- 跨批次趋势、人才九宫格和排名。
- 智能数据清洗、AI 评语和异常评分识别。
- 自动短信、电话或第三方消息提醒。
- 从外部系统导入历史答卷。

## 3. 已确认的产品决策

| 事项 | 已确认规则 |
|---|---|
| 题目模板 | 自评和他评使用同一份环评模板和相同题目 ID |
| 评分范围 | 环评计分题固定为 0–5 分 |
| 答卷权重 | 自评、同事评价、领导评价全部等权 |
| 题目权重 | 所有计分题等权 |
| 维度权重 | 不设置维度权重 |
| 每题得分 | 该员工该题所有有效已提交分值的算术平均值 |
| 员工最终分 | 该员工全部计分题得分的算术平均值 |
| 维度得分 | 该维度下全部计分题得分的算术平均值 |
| 案例说明 | 每个分值均有案例说明栏；管理员勾选的分值必须填写案例 |
| 未完成时计分 | 按当前有效答卷实时计算，标记为暂定分 |
| 截止后计分 | 截止或管理员锁定后生成最终分 |
| 无有效答卷 | 显示“暂无评分”，不得显示为 0 分 |
| 报告权限 | 首期仅管理员查看汇总分、维度分、逐题分和案例反馈 |
| 批次范围 | 一个批次可包含多个部门/小组，各组默认只在组内互评 |
| 跨组关系 | 不自动生成，由管理员人工补配 |
| 特殊人员 | 在批次内设置并人工配置关系，不使用联系人全局领导标签 |
| 历史稳定性 | 发布时冻结题目、人员和关系基础快照 |

## 4. 核心术语

| 术语 | 定义 |
|---|---|
| 环评模板 | 包含维度、0–5 分题目、行为描述和案例规则的统一模板 |
| 评价批次 | 一次完整的环评活动，包含模板、人员、小组、关系、时间和结果 |
| 参评人员 | 本批次中作为评价人、被评人或两者兼具的员工 |
| 评价小组 | 批次内用于自动生成互评关系的人员分组，默认来自联系人部门字段 |
| 普通人员 | 进入本组自动自评和全员互评网络的参评人员 |
| 特殊人员 | 不进入普通自动关系网络、由管理员人工配置关系的参评人员 |
| 评价关系 | 一条“谁评价谁”的任务记录 |
| 有效答卷 | 已提交且未被管理员作废的答卷 |
| 暂定分 | 批次进行中根据当前有效答卷实时计算的结果 |
| 最终分 | 批次锁定时生成并保持不可变的结果快照 |

## 5. 信息架构与模块

### 5.1 与原系统全局导航的关系

本次改造不得替换或重组原问卷系统的全局左侧菜单。全局菜单继续保留：

1. 问卷管理。
2. 360 环评。
3. 白名单管理。
4. 联系人。
5. 后台成员。

360 环评采用两层导航结构：

```text
原系统左侧点击“360环评”
→ 进入环评批次列表
→ 选择或新建一个批次
→ 进入批次详情及环评内部二级导航
```

批次详情内部的一级导航为：

- 环评概览。
- 题目模板。
- 人员与关系。
- 评估执行。
- 统计报告。

其中“人员与关系”包含参评人员、特殊人员和关系复核三个页面；“评估执行”包含评估进度和填写端预览；“统计报告”包含评价数据、个人报告和原始数据。环评内部导航只出现在 360 环评内容区，不占用全局左侧菜单位置。

### 5.2 管理员端

| 模块 | 核心职责 |
|---|---|
| 环评概览 | 展示批次配置进度、参评人数、关系数、异常数和计分规则 |
| 题目模板 | 维护维度、题目、0–5 分行为描述和案例必填分值 |
| 参评人员 | 选择多个部门/小组或自定义人员，确认批次内分组 |
| 特殊人员 | 标记批次内特殊人员并单独配置评价关系 |
| 关系复核 | 生成、检查、补配评价关系，处理单人组和遗漏 |
| 评估进度 | 设置开始/截止时间，查看任务完成度并进行人工提醒 |
| 评价数据 | 按被评人展示评价数量、总分和各维度分 |
| 个人报告 | 展示单个员工总分、维度表现、逐题得分和案例说明 |
| 原始数据 | 查看每份答卷、答题用时、有效状态和审计操作 |
| 结果导出 | 导出员工汇总、逐题明细、案例和原始答卷 |

### 5.3 员工端

| 模块 | 核心职责 |
|---|---|
| 我的评价任务 | 按批次展示自评和他评任务及完成进度 |
| 环评填写 | 清晰展示被评人、0–5 分行为选项和案例说明栏 |
| 提交结果 | 完成前后端校验并提交，成功后返回任务列表 |

员工端不提供“别人如何评价我”、个人得分或案例反馈入口。

## 6. 详细功能需求

### 6.1 环评模板与专用题型

#### 6.1.1 模板规则

- 一个新版环评批次只绑定一份环评模板。
- 同一份模板用于自评、同事评价和领导评价。
- 批次发布时将模板完整复制到批次快照中。
- 发布后修改原模板，不得影响已发布批次的填写和统计。
- 模板可以继续被后续批次复用。

#### 6.1.2 维度配置

- 支持新建、重命名、排序和删除维度。
- 维度包含稳定唯一 ID、名称和排序号。
- 每道计分题必须归属一个维度。
- 删除已有题目引用的维度前必须先迁移或删除相关题目。

#### 6.1.3 环评计分题

每道环评计分题至少包含：

- 稳定唯一题目 ID。
- 题目标题和补充说明。
- 所属维度 ID。
- 是否必填。
- 是否计入最终得分。
- 0、1、2、3、4、5 六个固定分值。
- 每个分值对应的行为描述。
- 案例说明提示语。
- 案例必填分值集合，例如 `[0, 4, 5]`。

所有分值均显示案例说明栏。若用户选择的分值属于案例必填集合，案例说明必须填写非空白内容；其他分值案例选填。

#### 6.1.4 模板快照结构

```json
{
  "version": 2,
  "dimensions": [
    { "id": "dim-integrity", "name": "诚信", "order": 1 }
  ],
  "questions": [
    {
      "id": "q-integrity-01",
      "type": "evaluation_score",
      "label": "人无信不立",
      "description": "",
      "dimensionId": "dim-integrity",
      "required": true,
      "countInScore": true,
      "options": [
        { "score": 0, "label": "说谎，隐瞒事实" },
        { "score": 1, "label": "不说谎，不散布谣言" },
        { "score": 2, "label": "做错后主动承认错误" },
        { "score": 3, "label": "看到问题敢于指出" },
        { "score": 4, "label": "纠正负面影响团队的行为" },
        { "score": 5, "label": "帮助建立诚信机制" }
      ],
      "casePrompt": "请填写具体案例，做到有理有据",
      "caseRequiredScores": [0, 4, 5]
    }
  ]
}
```

### 6.2 批次配置

批次基础信息包括：

- 批次名称。
- 统一环评模板。
- 开始时间。
- 截止时间。
- 批次状态。
- 创建人和创建时间。
- 实际锁定人、锁定时间。
- 模板快照。

开始时间必须早于截止时间。草稿状态允许修改；发布后模板快照不可修改。

### 6.3 参评人员与评价小组

- 联系人模块是参评人员姓名、工号、手机号、部门、职位等信息的唯一基础数据源。
- 新建批次不要求重复导入 Excel；管理员从联系人模块选择本期参评范围。
- 支持一次选择多个联系人部门/小组，系统自动预览符合条件的联系人及人数。
- 支持从联系人中单独追加或移除人员。
- 支持复制上一批次的人员范围，再根据本期联系人变化进行调整。
- 只有联系人模块中尚不存在相关员工时，才先通过联系人模块的 CSV 导入能力补充人员。
- 同一联系人同一批次只能出现一次。
- 每名参评人员必须有一个批次内评价小组。
- 默认使用联系人 `department` 作为小组名称，但管理员可在草稿阶段调整。
- 管理员确认人员范围后，系统将所选人员写入 `EvalCycleParticipant`，保存联系人 ID、姓名、工号、部门、职位和小组快照。
- 评价关系生成和批次统计读取 `EvalCycleParticipant`，不直接读取实时联系人表。
- 草稿阶段提供“同步联系人变更”，同步前展示新增、移除、调组和资料变化差异，由管理员确认后应用，不静默修改参评范围。
- 发布后人员快照冻结，联系人后续改名、调组、入职或离职均不自动改写本批次。
- 联系人中新增加的员工不会自动加入已经创建的批次，需要管理员在草稿阶段同步或手动添加。
- 普通人员进入本组自动关系生成。
- 特殊人员完全跳过自动关系生成。

### 6.4 特殊人员

- 特殊人员只在当前批次生效。
- 设置为特殊人员不会修改联系人全局标签。
- 管理员可分别配置“谁评价他”和“他评价谁”。
- 特殊人员也使用本批次统一题目模板。
- 特殊人员的评价分值与其他答卷等权。
- 发布前必须完成特殊人员关系配置，或登记明确豁免原因。

### 6.5 自动生成评价关系

对每个评价小组分别计算。若某组有 `N` 名普通人员：

```text
自评关系数 = N
组内他评关系数 = N × (N - 1)
自动关系总数 = N²
```

生成规则：

1. 每名普通人员生成一条本人评价本人的 `self` 关系。
2. 每名普通人员对同组其他普通人员各生成一条 `peer` 关系。
3. 不自动生成跨组关系。
4. 不为特殊人员生成任何自动关系。
5. 跨组、领导或其他例外关系由管理员人工创建。
6. 同一批次内同一评价人和被评人只能存在一条有效关系。

重新生成限制：

- 仅草稿批次可以重新生成。
- 批次不存在任何已提交答卷时才允许重新生成。
- 重新生成只替换自动关系，保留人工关系。
- 已提交关系永远不能被重新生成流程删除。

### 6.6 关系复核与豁免

复核列表按参评人员展示：

- 姓名、工号、评价小组和普通/特殊类型。
- 自评是否配置。
- 应收和已收评价数量。
- 需要评价和已完成评价数量。
- 自动、人工或混合来源。
- 异常类型和处理入口。

必须识别以下异常：

- 缺少自评。
- 无人评价。
- 没有需要完成的评价任务。
- 单人组无法互评。
- 特殊人员关系未配完整。
- 参评人员无评价小组。
- 重复评价关系。
- 关系指向非本批次参评人员。

管理员可为合理例外登记豁免类型和原因。豁免必须保留操作人和时间，不能通过静默忽略异常实现。

### 6.7 发布与填写

发布前系统执行完整校验：

- 已绑定有效环评模板。
- 至少存在一道计入得分的环评题。
- 计分题均有维度和完整 0–5 分行为描述。
- 至少存在一名参评人员。
- 所有普通人员都有自评关系。
- 每名被评人至少有一位他人评价，或已登记豁免。
- 特殊人员配置完整或已登记豁免。
- 开始时间和截止时间合法。

校验失败时禁止发布，并提供可跳转的处理入口。校验通过后，系统在同一事务中冻结模板、人员和关系基础快照并进入进行中状态。

员工填写要求：

- 只有当前登录联系人作为评价人的关系才可访问。
- 只有进行中且处于允许填写时间范围的批次才可提交。
- 列表明确区分自评和他评，并显示他评对象姓名。
- 打开答卷时记录开始时间。
- 同一关系在同一时刻只能有一份有效答卷；答卷被作废并重新开放后允许再次提交，新答卷成为当前有效答卷。
- 提交使用数据库事务同时创建答卷和更新关系状态。
- 前端与后端均校验必答题、0–5 分范围和案例必填规则。
- 提交后返回任务列表并刷新完成进度。

建议的环评答案结构：

```json
{
  "q-integrity-01": {
    "score": 4,
    "caseText": "在项目复盘中主动纠正了错误数据并同步相关同事。"
  }
}
```

### 6.8 评估进度

评估进度同时提供两个口径：

1. **任务完成率**：有效已提交关系数 ÷ 当前全部有效关系数。
2. **完成评估人数**：已收有效评价数达到应收评价数的被评人数。

页面展示：

- 被评估人数、完成评估人数、总任务数、已提交数和任务完成率。
- 按小组统计完成情况。
- 按评价人展示已完成/应完成任务数。
- 未开始、进行中、已完成状态。
- 最后提交时间。
- 单人提醒和批量提醒入口。

首期提醒仅提供站内操作入口和名单复制/导出，不接入第三方消息渠道。

## 7. 评分计算规则

### 7.1 有效答案集合

对被评员工 `e` 和计分题 `q`，定义 `A(e,q)` 为：

- 评价关系的被评人为 `e`。
- 答卷已经提交。
- 答卷状态为有效。
- 题目 `q` 存在合法的 0–5 数值答案。

若题目允许不必答，未作答的该题不进入该题分母；答卷的其他题目仍可参与计算。

### 7.2 每题得分

```text
QuestionScore(e,q) = Σ A(e,q).score ÷ Count(A(e,q))
```

例：某题自评为 5 分，三份他评分别为 1、2、4 分：

```text
(5 + 1 + 2 + 4) ÷ 4 = 3.00
```

自评、同事评价和领导评价不设置权重，均作为一份独立有效答案参与算术平均。

### 7.3 维度得分

设维度 `d` 下有得分的计分题集合为 `Q(e,d)`：

```text
DimensionScore(e,d)
= Σ QuestionScore(e,q) ÷ Count(Q(e,d))
```

维度分仅用于维度展示，不用于反向计算员工最终分。

### 7.4 员工总分

设该员工所有有得分且 `countInScore=true` 的题目集合为 `Q(e)`：

```text
TotalScore(e)
= Σ QuestionScore(e,q) ÷ Count(Q(e))
```

员工总分严格按照全部计分题等权平均计算，不能使用各维度得分再平均，因为不同维度的题目数量可能不同。

### 7.5 精度与展示

- 计算过程中保留数据库或运行时完整精度。
- 页面与导出默认显示两位小数。
- 展示时使用四舍五入。
- 不允许用逐层四舍五入后的维度分计算总分。
- 某员工没有任何有效题目得分时，结果为 `null`，页面显示“暂无评分”。

### 7.6 自评与他评对照

个人报告可以单独展示：

- 自评分：唯一有效自评答案的分值。
- 他评平均：除自评外所有有效答案的平均值，包含同事和领导评价。
- 综合得分：仍按全部有效答案逐份等权计算。

自评与他评对照只用于分析，不改变综合得分公式。

### 7.7 暂定与最终结果

- 进行中每次提交、作废或恢复答卷后，重新计算受影响被评人的暂定结果。
- 暂定结果必须显示已收/应收评价数和“暂定”标识。
- 截止时停止填写，但结果仍可处于未锁定状态。
- 管理员锁定后，对全部员工执行一次完整重算并保存最终结果快照。
- 最终结果快照保存总分、维度分、逐题分、有效答卷数、应收答卷数、模板版本和锁定时间。
- 已锁定结果不得因原模板、联系人或原始答卷后续变化而改变。

## 9. 生命周期与权限

### 9.1 批次状态

```text
draft（草稿）
→ published（已发布）
→ closed（已截止）
→ locked（已锁定）
→ archived（已归档）
```

| 状态 | 允许操作 | 禁止操作 |
|---|---|---|
| 草稿 | 修改模板、人员、特殊人员、关系和时间；重新生成关系 | 员工填写、查看正式结果 |
| 已发布 | 查看进度、提醒、延长截止时间、非破坏性人工补配；仅在开始和截止时间之间允许员工填写 | 修改模板快照、批量删除人员、破坏性重新生成 |
| 已截止 | 查看暂定结果、延长时间并重新开放、准备锁定 | 员工提交 |
| 已锁定 | 查看和导出最终结果、归档 | 提交、修改关系、作废或恢复答卷、重新计算口径 |
| 已归档 | 只读查看和导出 | 所有修改和删除 |

已发布批次不提供物理删除。草稿且没有任何答卷时才允许删除。

已发布状态的页面展示根据时间进一步派生：当前时间早于开始时间时显示“未开始”，处于开始和截止时间之间时显示“进行中”。到达截止时间后由系统转为已截止。

### 9.2 权限

- 管理员可管理批次、人员、关系、答卷有效性、结果和导出。
- 员工只能查看以自己为评价人的任务。
- 员工只能提交属于自己的、当前允许填写的关系。
- 员工不能访问被评人的汇总结果、他评答案和评价人列表。
- 所有权限在后端接口强制校验，不能只依赖页面隐藏。

### 9.3 审计

以下操作必须写入环评审计日志：

- 发布、截止、重新开放、锁定和归档。
- 添加或移除参评人员。
- 设置或取消特殊人员。
- 人工增加、删除和豁免评价关系。
- 作废和恢复答卷。
- 重新计算结果。

审计记录包含批次、操作类型、对象、操作前后摘要、管理员、时间和原因。

## 12. 异常与错误处理

| 场景 | 处理 |
|---|---|
| 草稿批次被员工访问 | 返回无可填写任务或明确的未发布提示 |
| 已截止或锁定后提交 | 后端拒绝并提示批次已结束 |
| 重复提交同一关系 | 事务和唯一状态更新共同拦截 |
| 必答题未答 | 前端定位题目，后端返回具体题目名称 |
| 分值不是 0–5 整数 | 后端拒绝提交 |
| 案例必填但内容为空 | 前后端拒绝并定位具体题目 |
| 无评价小组 | 列入发布前异常，禁止自动生成 |
| 单人组 | 保留自评并标记无人他评，要求人工补配或豁免 |
| 特殊人员未配置 | 发布前检查失败 |
| 已有答卷后重新生成 | 拒绝破坏性操作 |
| 已提交关系删除 | 拒绝删除，可作废答卷但保留关系 |
| 锁定后修改答卷有效性 | 拒绝操作 |
| 计算中存在无效或缺失值 | 排除该题答案并记录计算异常日志 |

作废与重新填写规则：

- 进行中批次的当前答卷被作废后，关系状态回到 `pending`，员工可以重新填写。
- 新答卷提交后成为 `EvalRelation.responseId` 指向的当前有效答卷，旧答卷继续保留为无效历史记录。
- 若关系已经产生新的有效答卷，旧答卷不得直接恢复为有效，避免同一关系出现两份有效答卷。
- 已截止但未锁定的批次需要先重新开放，员工才能补填。
- 管理员也可以为无法补填的关系登记豁免原因；豁免关系不计入应完成任务分母。

### 15.2 人员与关系

- 原系统左侧菜单类目和入口保持不变。
- 点击“360 环评”先进入批次列表，进入批次后才显示环评内部二级导航。
- 新建批次可直接从联系人模块按部门/小组选择人员，无需重复导入人员资料。
- 可复制上一批次人员范围，并在草稿阶段确认联系人变化差异。
- 同一批次可选择多个小组。
- 各组只在本组内自动互评。
- `N` 名普通人员严格生成 `N²` 条自动关系。
- 特殊人员不进入自动关系网络。
- 跨组和特殊人员关系可人工配置。
- 关系异常未处理或未豁免时不能发布。

### 15.3 填写

- 员工只能填写分配给自己的任务。
- 草稿、截止和锁定状态均不能提交。
- 0–5 分范围和案例必填规则前后端一致。
- 同一关系不能重复提交。
- 员工端看不到别人如何评价自己。

### 15.4 评分

- 自评、同事和领导答卷逐份等权。
- 每题得分等于该题所有有效答案平均值。
- 维度分等于该维度题目得分平均值。
- 员工总分等于全部计分题得分平均值。
- 作废或恢复答卷后暂定分正确更新。
- 无有效答卷显示“暂无评分”。
- 页面与导出显示两位小数且结果一致。

### 15.5 最终结果

- 进行中结果明确标注暂定。
- 锁定前执行完整重算。
- 锁定后最终结果、模板和关系不可修改。
- 已锁定批次只能查看、导出和归档。

### 15.6 回归

- 普通问卷创建、发布和填写正常。
- 问卷白名单和联系人功能正常。
- 企微 OAuth 和开发测试登录边界正常。
- 普通问卷统计与导出结果不受环评模型影响。

## 16. 测试重点样例

1. 某题自评 `5`，三份他评 `1、2、4`，该题综合得分必须为 `3.00`。
2. 四道题得分为 `1、2、3、4`，员工总分必须为 `2.50`。
3. 两个维度分别有 1 道题和 3 道题时，总分仍按 4 道题直接平均，不能平均两个维度分。
4. 选择被配置为案例必填的分值但案例为空，前端提示且后端拒绝。
5. 作废一份他评后，该答案从每题分母中移除并重新计算暂定分。
6. 恢复该答卷后，计算结果恢复。
7. 只有自评已提交时，暂定分按自评计算并明确显示 `1/应收数`。
8. 没有任何有效答卷时，总分、维度和题目均显示暂无评分。
9. 三个普通人员的组生成 3 条自评和 6 条他评，共 9 条关系。
10. 同组包含一名特殊人员时，只对普通人员生成自动关系，特殊人员关系全部人工配置。
11. 已有答卷后调用重新生成、删除关系或删除批次均被拒绝。
12. 锁定后作废、恢复、提交和修改关系均被拒绝。

## 17. 最终页面流程

```text
原系统左侧点击“360环评”
→ 进入环评批次列表
→ 创建或进入一个批次
→ 创建或选择统一环评模板
→ 配置维度、0–5 分行为描述和案例规则
→ 从联系人模块选择多个小组或复制上一批次范围
→ 预览并确认本期参评人员快照
→ 确认批次内特殊人员
→ 自动生成普通人员关系
→ 人工配置特殊及跨组关系
→ 处理或豁免全部异常
→ 发布并冻结快照
→ 员工逐份填写
→ 管理员查看进度和暂定结果
→ 截止或延长填写时间
→ 锁定并生成最终结果
→ 查看、导出并归档
```

本规格是后续实施计划、数据库迁移、接口设计、页面开发和验收测试的唯一产品基线。若后续需要增加权重、员工报告发布或跨批次分析，应单独提出变更并形成新版本规格。
