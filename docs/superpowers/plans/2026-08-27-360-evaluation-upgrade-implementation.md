# 360 环评方案 B 实施计划

**日期**：2026-08-27<br>
**需求基线**：`docs/superpowers/specs/2026-08-27-360-evaluation-upgrade-design.md` v1.1<br>
**实施原则**：增量迁移、旧功能不改行为、旧环评批次可读、新环评批次使用统一模板与快照。

## 1. 当前基线

- 后端 NestJS 构建通过。
- 后端尚无 `src/**/*.spec.ts` 单元测试，先为评分和关系生成纯函数补测试。
- 前端存在一个原有未使用变量导致 TypeScript 构建失败，实施时一并清理。
- Docker Desktop 当前未运行；代码验证先使用构建和单元测试，最终本地联调前再启动 Docker。
- 现有 360 仅支持单部门、三份模板和原始导出，本次在原模块上增量升级。

## 2. 数据库与兼容层

涉及文件：

- `backend/prisma/schema.prisma`
- `backend/prisma/migrations/20260827000000_upgrade_360_evaluation/migration.sql`

实施内容：

1. 扩展 `EvalCycle`：统一模板、模板快照、时间范围、锁定和归档字段，并增加新版标识。
2. 新增 `EvalCycleParticipant`：保存联系人与组织信息的批次快照、组别、普通/特殊模式和豁免信息。
3. 扩展 `EvalRelation`：增加状态、异常原因和更新时间。
4. 扩展 `SurveyResponse`：增加环评关系、开始时间、有效状态及作废/恢复信息。
5. 新增 `EvalEmployeeResult` 和 `EvalAuditLog`。
6. 保留旧的三模板字段和旧关系 ID，不修改普通问卷数据。

验证：Prisma 格式校验、客户端生成、后端构建。

## 3. 后端领域服务

涉及文件：

- `backend/src/eval.types.ts`
- `backend/src/eval-scoring.ts`
- `backend/src/eval.service.ts`
- `backend/src/eval.controller.ts`
- `backend/src/eval-fill.controller.ts`

实施内容：

1. 使用明确类型规范统一模板结构和批次状态。
2. 新增联系人候选范围、按部门选择、人员批量保存、单人增减和复制上期范围接口。
3. 关系生成只读取批次人员快照，并按每组普通人员分别生成 `N²` 条关系。
4. 新版所有关系使用同一模板；特殊人员和跨组关系继续人工配置。
5. 增加发布前检查、发布、截止、重新开放、锁定和归档操作。
6. 填写端读取模板快照，后端校验 0–5 分、必答题和案例必填规则。
7. 每次有效答卷变化后重算被评人暂定结果；锁定时全量重算并冻结最终结果。
8. 新增概览、进度、员工结果、个人报告和原始答卷接口。
9. 扩展 Excel 导出为员工汇总、逐题、原始答卷和案例说明。

验证：评分纯函数测试、关系生成测试、状态边界测试、后端构建。

## 4. 管理端改造

涉及文件：

- `frontend/src/EvalPages.tsx`
- `frontend/src/index.css`
- `frontend/src/App.tsx`

实施内容：

1. 保留原系统全局左侧菜单。
2. 360 入口先显示批次列表；进入批次后显示环评概览、题目模板、人员与关系、评估执行、统计报告二级导航。
3. 新建批次仅录入名称，随后在批次详情完成模板、人员和时间配置。
4. 模板页支持维度、题目、0–5 行为描述以及案例必填分值多选。
5. 人员页支持按联系人部门批量选择、单人增减、复制上期、设置特殊人员和调整批次小组。
6. 关系页支持生成、复核、人工关系和异常提示。
7. 执行与报告页展示任务进度、员工结果、个人报告和原始答卷。
8. 修复现有前端未使用变量，恢复构建基线。

验证：TypeScript 构建、关键页面加载、菜单和路由回归。

## 5. 员工填写端

涉及文件：

- `frontend/src/EvalPages.tsx`
- `frontend/src/index.css`

实施内容：

1. 保留企微登录与受控本地测试登录。
2. 任务列表按批次展示进度并区分自评、同事评价和领导评价。
3. 用统一模板快照渲染固定 0–5 分行为选项。
4. 每题始终显示案例栏；命中管理员配置分值时动态必填。
5. 展示后端返回的状态、时间范围和校验错误。

验证：前端构建；本地使用两个以上联系人完成自评、他评、评分汇总闭环。

## 6. 本地运行与验收

1. 执行后端单元测试和前后端构建。
2. 启动 Docker Desktop 后运行 `docker compose up -d --build`。
3. 执行 Prisma 迁移与种子数据。
4. 使用本地管理员登录创建新版批次。
5. 选择联系人、生成关系、发布并使用本地测试身份填写。
6. 核对任务完成率、题目平均分、员工总分和导出结果。
7. 回归普通问卷、白名单、联系人和后台成员页面。

## 7. 提交策略

- 数据模型与后端基础一笔提交。
- 管理端与填写端一笔提交。
- 测试、文档和本地验收修正一笔提交。
- 不提交用户现有的未跟踪原型、临时文件或其他文档。
