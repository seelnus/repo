# 360 环评发布后补充成员实施计划

1. 为发布后补人建立独立的后端计算结构，复用现有人员快照规划和多小组关系生成器，只保留涉及本次新增成员的关系差集。
2. 新增预览与正式补人接口，统一校验 V2、已发布、未截止、有效模板、启用联系人、主部门和成员重复状态。
3. 在单个 Prisma 事务中追加人员快照、小组快照、自动关系和审计日志；不执行任何更新或删除已有成员、关系和答卷的操作。
4. 补充后端测试，覆盖已有答卷仍可补人、双向互评、多成员与多小组去重、人工关系冲突、重复成员、截止状态和事务写入内容。
5. 在“参评人员”页为已发布未截止批次增加“补充成员”入口，候选项排除已有成员并用完整部门路径和联系人 ID 区分同名人员。
6. 增加影响预览弹窗，展示新增成员、自评、互评、受影响原评价人、截止时间和已有员工新增待办提示。
7. 补人成功后刷新人员列表，并通知关系复核区域刷新；失败时保留当前选择并展示后端具体原因。
8. 执行后端完整测试、前后端生产构建、差异检查，并在本地已发布测试批次完成一次真实接口验收。
9. 仅提交本次计划、接口、页面和测试文件，不包含工作区原有未提交内容；不推送或发布正式环境。
