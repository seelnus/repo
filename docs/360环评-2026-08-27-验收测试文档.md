## 2. 本次调整总结

### 2.1 页面与导航

- 保留原问卷系统左侧菜单结构：问卷管理、360 环评、白名单管理、联系人、后台成员。
- 进入“360 环评”后先显示批次列表。
- 进入新版批次后提供五个二级模块：
  - 环评概览
  - 题目模板
  - 人员与关系
  - 评估执行
  - 统计报告
- 新版批次列表展示参评人数、关系数、状态及“进入批次”操作。

### 2.2 新旧批次兼容

- 历史批次保留为 `version = 1`，继续使用旧版详情和数据逻辑。
- 新建批次使用 `version = 2`，进入新版五模块流程。
- 系统不会自动把旧批次转换成新版，避免旧版多模板数据被错误合并。
- 普通问卷、联系人、白名单和后台成员数据不迁移、不重写。

### 2.3 统一环评模板

- 一个新版环评批次只使用一份统一环评题目模板。
- 当前已实现题型为 `evaluation_score`，每题固定 0–5 分。
- 每个分值都可配置行为描述。
- 每道评分题始终提供案例说明栏。
- 管理员可勾选需要强制填写案例的分值，例如 0、4、5 分。
- 发布时保存模板快照，发布后模板变化不影响当前批次答卷。

### 2.4 人员范围与快照

- 批次人员候选来源于现有“联系人”模块。
- 管理员可按联系人部门筛选并批量加入，也可单独增减人员。
- 加入批次后保存姓名、部门、职位等人员快照，后续联系人资料变化不应改写历史批次。
- 支持批次内分组。
- 支持把人员设置为特殊人员，由管理员人工配置评价关系。
- 人员范围是批次级数据，不需要每次重新导入联系人文件。

### 2.5 评价关系

- 普通人员按批次快照和组别生成评价关系。
- 同一组有 `N` 名普通人员时，生成 `N²` 条关系：每人 1 条自评和 `N-1` 条同组他评。
- 特殊人员不进入普通关系自动生成，需人工配置。
- 支持关系复核、异常提示、人工新增和删除未填写关系。
- 已产生有效答卷的关系不能直接删除。

### 2.6 批次生命周期

- 新版批次状态流程：草稿 → 已发布 → 已截止 → 已锁定 → 已归档。
- 草稿状态允许配置模板、人员和关系。
- 发布前执行完整性检查。
- 已截止批次可以重新开放并设置新截止时间。
- 已截止批次可以锁定结果。
- 已锁定批次可以归档。

### 2.7 员工作答与案例校验

- 员工端读取批次发布时的统一模板快照。
- 自评、同事评价和领导评价使用同一套题目。
- 必答评分题必须选择 0–5 分。
- 选择被配置为案例必填的分值时，案例为空不能提交。
- 同一评价任务提交后不能重复填写，除非管理员作废该答卷并允许重填。

### 2.8 评分规则

- 所有有效答卷等权，不设置自评、同事或领导额外权重。
- 单个员工某道题得分：该员工该题所有有效自评和他评答卷分值的算术平均值。
- 单个员工最终得分：该员工所有有效计分题题目得分的算术平均值。
- 维度分：该维度下有效计分题得分的算术平均值。
- 已作废答卷不参与计算。
- 没有有效评分时显示“暂无评分”，不能按 0 分处理。

### 2.9 执行、报告与导出

- 概览和执行模块展示任务进度、完成情况及异常。
- 统计报告展示员工总分、维度分、逐题得分、自评和他评对照。
- 个人报告展示逐题分值和案例说明。
- 管理员可作废答卷并填写原因，也可在条件允许时恢复答卷。
- 锁定结果后不能再作废或恢复答卷。
- 支持导出员工汇总、逐题明细、原始答卷及案例说明。

### 2.10 本地运行修正

- Vite API 代理支持本机和 Docker 两种目标地址。
- Docker 前端通过 `VITE_API_PROXY_TARGET=http://app-backend:3100` 访问后端。
- 数据库迁移由后端容器启动时自动执行。
